# Установка «Фиды каталога Tilda»

Программа забирает каталог Tilda Store и публикует его в Яндекс Бизнес, 2ГИС и, если нужно, на второй
сайт Tilda. Работает в Docker, образ — [`midmen/tildatosites`](https://hub.docker.com/r/midmen/tildatosites).

Этот репозиторий — установщик: один playbook Ansible ставит программу на чистый сервер. В нём задаются
только адрес, владелец и, при желании, версия. Всё остальное администратор потом настраивает в редакторе.

## Что нужно

- **Сервер.** Ubuntu, Debian, RHEL, Oracle Linux, Rocky, Alma или Fedora; доступ по ssh от root или
  от пользователя с sudo. Хватает 1 CPU и 1 ГБ памяти, плюс место под фото каталога.
- **Управляющая машина.** Ваш компьютер с Ansible 2.15 или новее (`pip install -U ansible-core`) и этим
  репозиторием. На сервер Ansible ставить не нужно.
- **Домен** для редактора и фидов, например `feed.company.ru`, с DNS-записью на сервер. Если HTTPS
  ставит сам playbook (`feed_https: true`), на сервере должны быть свободны порт 80 (через него
  Let's Encrypt подтверждает домен) и порт HTTPS — 443 или свой (`feed_https_port`).

## Установка

```
git clone https://github.com/MiDmeN/tildatosites-install.git
cd tildatosites-install
cp inventory.example.ini inventory.ini                                       # адрес сервера
cp group_vars/places_feed/vars.yml.example group_vars/places_feed/vars.yml   # несколько строк, см. ниже
ansible-playbook playbook.yml
```

`inventory.ini` и `vars.yml` — ваши файлы. Они в `.gitignore` и в репозиторий не попадают; в репозитории
только образцы `*.example`.

### inventory.ini — какой сервер

Впишите адрес сервера и пользователя, под которым Ansible заходит по ssh (по ключу):
```
[places_feed]
feed-server ansible_host=203.0.113.10 ansible_user=root
```
Не root, а пользователь с sudo — `ansible_user=admin`; если sudo спрашивает пароль, запускайте playbook
с `--ask-become-pass`. Проверить, что сервер доступен: `ansible places_feed -m ping`.

### vars.yml — адрес, владелец, HTTPS

С доменом, HTTPS ставится сам (DNS-запись домена указывает на сервер, свободны порты 80 и 443):
```
feed_public_url: https://feed.company.ru
feed_owner: ivanov
feed_https: true
```

Порт 443 на сервере занят — HTTPS на другом порту:
```
feed_public_url: https://feed.company.ru:8443
feed_owner: ivanov
feed_https: true
feed_https_port: 8443
```

HTTPS даёт ваш прокси (nginx и т. п.) на этом же сервере — приложение слушает `127.0.0.1:8080`:
```
feed_public_url: https://feed.company.ru
feed_owner: ivanov
feed_https: false
```

Проба без домена, по IP и http:
```
feed_public_url: http://203.0.113.10:8080
feed_owner: ivanov
feed_https: false
feed_bind: 0.0.0.0
```

`feed_owner` — логин, под которым вы войдёте в редактор; `owner` и адреса `example.com` playbook не примет.

Все переменные `vars.yml`:

| Переменная | Что это |
|---|---|
| `feed_public_url` | адрес, на котором будут редактор (`/admin/`) и фиды для площадок |
| `feed_owner` | логин владельца — первого пользователя редактора |
| `feed_https` | `true` — сертификат и HTTPS ставятся сами; `false` — HTTPS даёт ваш прокси, приложение слушает `127.0.0.1:8080` |
| `feed_https_port` | необязательно: порт HTTPS, если 443 занят; тогда он же в адресе — `https://feed.company.ru:8443` |
| `feed_version` | необязательно: без неё ставится последняя версия (`latest`); `"2.0.1"` — закрепить версию |

Playbook сам:
- ставит Docker;
- создаёт папку `/opt/places-feed`;
- открывает порты в firewalld или ufw;
- скачивает образ и запускает программу.

В конце он выводит версию, адрес редактора и **ссылку для первого входа владельца**. Ссылка действует
72 часа. Там же итог проверки настроек: сразу после установки в нём есть `✗` про фид Tilda — так и должно
быть, фид задаётся в редакторе.

## Первая настройка — в редакторе

Владелец входит по ссылке, задаёт пароль и в разделе «Настройки» заполняет:

1. **Организация** — название в фидах и юрлицо.
2. **Источник** — ссылку на YML-фид Tilda Store (Tilda → Магазин → Товары → Экспорт). Без неё фиды
   не собираются.
3. **Обновление** — включить расписание, время и часовой пояс. Кнопка «Обновить сейчас» собирает всё
   сразу, не дожидаясь расписания.
4. **Площадки** — Яндекс Бизнес, 2ГИС и перенос на второй сайт Tilda.
5. **Каталог** — какие карточки не публиковать и какие категории им давать на площадках.
6. **Telegram-бот** — токен бота для уведомлений; проверить можно кнопкой «Отправить тестовое сообщение».
7. **Резервные копии** — S3-хранилище и пароль шифрования.
8. **Перенос на сайт**, если он нужен, — каталоги Tilda и доступ к коннектору 1С.

Остальных пользователей владелец заводит в разделе «Пользователи».

Что ещё не задано, показывает проверка `docker compose exec web python doctor.py --online`:
`✗` — без этого не заработает, `!` — стоит настроить.

### Ключи при установке (необязательно)

Ключи можно задать и сразу при установке — в `group_vars/places_feed/vault.yml` (образец
`vault.yml.example`), зашифровав его `ansible-vault encrypt`. Запуск тогда — с `--ask-vault-pass`.
Файл обязателен, только если образ лежит в закрытом реестре.

Ключ, который уже лежит на сервере в `secrets/`, playbook не перезаписывает: ни значением из `vault.yml`,
ни пустым. Новые ключи он создаёт — из `vault.yml`, а без него пустыми. Чтобы заменить ключ, удалите его
файл в `secrets/` и запустите playbook или введите ключ в «Настройках» редактора.

## Папка установки на сервере

```
/opt/places-feed/
  compose.yaml, compose.https.yaml, .env   запуск (создаёт playbook, руками не править)
  config/                                  начальные настройки сайта и профиль (обычно пусто)
  secrets/                                 ключи, заданные при установке
  data/                                    тексты, пользователи, настройки редактора, журнал — главное, что бэкапить
  media/                                   загруженные фото
  public/                                  опубликованные фиды и фото
  report/                                  отчёты запусков
  caddy/                                   сертификаты HTTPS (при feed_https: true)
```

Службы:
- `web` — редактор на `/admin/` и фиды;
- `scheduler` — обновление по расписанию;
- `https` — прокси, только при `feed_https: true`.

## Обслуживание

```
cd /opt/places-feed
docker compose ps                                  # что запущено
docker compose logs -f web                         # журнал
docker compose exec web python doctor.py --online  # проверка настроек и фида Tilda
docker compose exec web python feed.py version     # установленная версия
docker compose run --rm web run                    # обновить фиды сейчас, не дожидаясь расписания
docker compose exec web python admin.py users invite <логин> --role admin   # ссылка для входа
```

- **Обновление программы.** `git pull` в этом репозитории и снова `ansible-playbook playbook.yml`:
  скачается свежий `latest` (или версия из `feed_version`, если она закреплена). Данные, пользователи
  и настройки редактора сохраняются.
- **Смена адреса или HTTPS.** Поправить `vars.yml` и снова запустить playbook.
- **Резервные копии.** «Настройки → Резервные копии», копия делается каждый день.
- **Перенос на новый сервер.**
  1. Установить программу этим playbook.
  2. Войти по ссылке владельца.
  3. В «Настройки → Резервные копии» указать то же хранилище и тот же пароль копий.
  4. В «Список копий и восстановление» нажать «Восстановить».

Остальные переменные (папка установки, порты, профиль сайта, закрытый реестр) описаны в
`roles/places_feed/defaults/main.yml`. Обычно их менять не нужно.

## Установщик в своём репозитории (коллекция Ansible)

Если у вас свой репозиторий с настройками установки — например, чтобы ставить через CI, — установщик можно
подключить как коллекцию `midmen.tildatosites` нужной версии, не копируя его:

```
# requirements.yml
collections:
  - name: https://github.com/MiDmeN/tildatosites-install.git
    type: git
    version: v1.0.0
```
```
# deploy.yml
- import_playbook: midmen.tildatosites.install
```
```
ansible-galaxy collection install -r requirements.yml -p .collections
ANSIBLE_COLLECTIONS_PATH=.collections ansible-playbook -i inventory.ini deploy.yml
```
Переменные — в `group_vars/places_feed.yml` рядом с вашим `inventory.ini`. Свои службы рядом с приложением
подключаются файлами compose из `feed_compose_files`: они кладутся в папку установки после `compose.yaml`.

Версии установщика — git-теги `vX.Y.Z`; однажды выпущенная версия не меняется.

## Если не работает

- **Playbook остановился на «Проверить обязательные переменные».** Не заполнен `vars.yml`: адрес
  или логин владельца.
- **`doctor.py` показывает `✗`.** В каждой строке сказано, что и где задать.
- **Нет ссылки для входа.** Владелец уже задал пароль. Новую ссылку выдаёт `admin.py users invite`
  (команда из раздела «Обслуживание»).
- **Не выпускается сертификат.** Проверьте DNS-запись домена и что порт 80 и порт HTTPS открыты снаружи;
  журнал прокси — `docker compose logs https`.
